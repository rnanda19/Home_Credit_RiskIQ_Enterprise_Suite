# Model Registry — Home Credit RiskIQ Enterprise Suite

This is a lightweight, file-based model registry: a single source of truth
for which trained-model artifacts exist across the suite's 5 Mega Projects,
who owns each one, who else depends on it, and a promotion log to fill in
every time a notebook is re-run and produces a new champion. It replaces
the informal state that existed before this file: each problem's own
`MODEL_CARD.md` names its own bundle path, but there was no single place
that showed the whole suite's artifact map or a version/promotion history.

This is **not** a live registry service (no MLflow, no automatic version
promotion, no programmatic rollback) — see `SECURITY.md` and the
production-readiness gap analysis for that distinction. What it does give:
one place to see every real model artifact this suite produces, exactly
which notebook owns it, exactly which other notebooks silently depend on
it, and a durable log of what was promoted, when, and why.

Built by reading all 30 `model_cards/*.md` files across the 5 Mega
Projects on 2026-09-08 and extracting each one's declared `Bundle:`,
`Bundle reused:`, `Hard dependency:`, `Soft dependency:`, `Outputs:`, or
`Service:` line verbatim. Every artifact path below is `.gitignore`d by
design (see `**/decision_engine/artifacts/` and `**/decision_engine/reports/`
in `.gitignore`) — these are generated files, regenerated by re-running the
owning notebook, never committed as binary blobs.

## Why champion algorithm isn't listed as a fixed value here

Every model-owning notebook in this suite trains multiple candidates
(typically `RandomForestClassifier`, `XGBClassifier`, `CatBoostClassifier`,
`LGBMClassifier`) under 5-fold CV and picks the champion dynamically by
mean CV score — the model cards explicitly state the repository "does not
hardcode or claim a specific champion" in the documentation, on purpose,
because a different environment/run could re-rank the top 2 candidates.
That means the *actual* algorithm behind e.g. `notebook_01_champion_model.joblib`
is only known for certain by whoever last ran that notebook. The Promotion
Log below exists to capture that fact every time it happens, rather than
this file asserting something that can silently go stale.

### Known cross-Mega-Project consumers of `MP1-01`

`MP1-01` (the Problem 1 credit-default champion) is the suite's most
heavily reused artifact — retraining it has a wider blast radius than any
other:

- MP2 Problem 1 (Expected Loss & Capital Requirement Estimation) reuses it directly ("Bundle reused (not owned by this notebook)").
- MP3 Problem 1 (Data-Driven Risk Tier Construction) lists it as a hard dependency.

Retraining `MP1-01` and promoting a new champion means MP2-01 and MP3-01
should be re-run afterward to stay consistent with the new model, even
though neither of those notebooks owns the artifact itself.

## Maintenance

Update this file whenever a notebook that owns a bundle is re-run with a
materially different result (new champion algorithm, retrained on new
data, a metric moving enough to matter) — add a row to the Promotion Log
above. If a new notebook is added that persists its own artifact, add it
to the "Owned Model Artifacts" table and its Mega Project's per-problem
table.
